### 1.1 AI Model Configuration (fixed 2026-11-06)

Runtime AI provider is OpenAI only. The model is read from the
`OPENAI_MODEL` env var, default `gpt-4o`; the key is `OPENAI_API_KEY`
(env only, never in code). Changing the model is a config change only:
no code change, and the advisor output is still re-validated against
the invoice and the approval policy before anything is signed or sent.
GPT-4o is the default, NOT a requirement: any OpenAI chat-completion
model may be used.

## 3. PayoutGuard (Own Runtime Validation) & PII Masking — and What APIMatic Is / Is Not

**APIMatic Context Plugin is a build-time tool only.** It gives the coding agent PayPal OpenAPI context while the Payouts client is written, so generated calls are type-correct against the PayPal Payouts OpenAPI specification. It does NOT run in the production request path, does NOT validate payloads at runtime, and does NOT mask PII. The full, auditable record of what APIMatic was actually used for is in `docs/APIMATIC.md`. The runtime validation below is our own hand-written `PayoutGuard` — it is not APIMatic output and must never be presented as such.

```typescript
// src/guard/payoutGuard.ts
import { PayoutItem } from '../models/PayoutItem';

// Approval policy (fixed 2026-11-06; demo sandbox caps, env-configurable).
// Human approval is mandatory before every batch. The AI recommends,
// the human approves, PayPal executes. No auto-execution path exists.
export const PER_ITEM_CAP_USD = 250;
export const PER_BATCH_CAP_USD = 500;
export const DAILY_CAP_USD = 1000;
export const RECIPIENT_ALLOWLIST_MAX = 20;

export class PayoutGuard {
  // Own runtime guard. NOT an APIMatic product. APIMatic was used at build time only (see docs/APIMATIC.md).

  /**
   * Enforces the approval policy before any PayPal call. Returns the
   * blocking reasons; an empty array means the batch may be approved.
   * Over-cap or off-allow-list batches are AWAITING_APPROVAL and are
   * never sent. A treasurer override still cannot exceed DAILY_CAP_USD.
   */
  public static validateBatchPolicy(batch: {
    items: PayoutItem[]; approved: boolean; spentTodayUsd: number;
    allowlist: string[];
  }): string[] {
    const errors: string[] = [];
    if (!batch.approved) errors.push('Batch has not been human-approved');
    const totalUsd = batch.items.reduce((s, i) => s + i.amount, 0); // amounts already converted to USD-equivalent for the cap check
    if (totalUsd > PER_BATCH_CAP_USD) errors.push(`Batch total $${totalUsd} exceeds per-batch cap $${PER_BATCH_CAP_USD}`);
    if (batch.spentTodayUsd + totalUsd > DAILY_CAP_USD) errors.push('Batch would exceed daily cap $' + DAILY_CAP_USD);
    batch.items.forEach((item, idx) => {
      if (item.amount > PER_ITEM_CAP_USD) errors.push(`Item ${idx} amount $${item.amount} exceeds per-item cap $${PER_ITEM_CAP_USD}`);
      if (!batch.allowlist.includes(item.recipientEmail)) errors.push(`Item ${idx} recipient is not on the allow-list`);
    });
    return errors;
  }

  /**
   * Masks PII before ANY data leaves the backend for the LLM.
   * Fixed 2026-11-06: the old regex (/(?<=^.{2}).(?=.*@)/g) was buggy
   * and only touched `receiver`. This version masks every string field
   * except an explicit allow-list (currency, status, country, amount).
   * Emails keep the first 2 chars of the local part + the domain, e.g.
   * global_vendor_eu@example.com -> gl***@example.com. Free-text fields
   * (note, email_subject, email_message) are replaced with [REDACTED].
   * Raw recipient emails are NEVER sent to the LLM.
   */
  public static maskEmail(email: string): string {
    const at = email.indexOf('@');
    if (at <= 0) return '***@***.com';
    const local = email.slice(0, at);
    const domain = email.slice(at + 1);
    return `${local.slice(0, 2)}***@${domain}`;
  }

  public static sanitizeForLLM(payload: any): any {
    const SAFE_KEYS = new Set(['currency', 'status', 'amount', 'value', 'fxRiskScore']);
    const mask = (value: any, key: string): any => {
      if (typeof value === 'string') {
        if (SAFE_KEYS.has(key)) return value;
        if (key.toLowerCase().includes('email') || key === 'receiver') return PayoutGuard.maskEmail(value);
        if (key === 'note' || key === 'email_subject' || key === 'email_message' || key === 'recipientNote') return '[REDACTED]';
        return '[REDACTED]';
      }
      if (Array.isArray(value)) return value.map((v, i) => mask(v, key));
      if (value && typeof value === 'object') {
        const out: any = {};
        for (const [k, v] of Object.entries(value)) out[k] = mask(v, k);
        return out;
      }
      return value;
    };
    return mask(JSON.parse(JSON.stringify(payload)), 'root');
  }

  /**
   * Validates structure against PayPal OpenAPI specs
   */
  public static validatePayoutPayload(payload: any): { valid: boolean; errors?: string[] } {
    const errors: string[] = [];
    if (!payload.sender_batch_header?.sender_batch_id) {
      errors.push("Missing required field: sender_batch_header.sender_batch_id");
    }
    if (!Array.isArray(payload.items) || payload.items.length === 0) {
      errors.push("Payload must contain at least one payout item");
    }
    
    payload.items?.forEach((item: any, idx: number) => {
      if (!item.amount?.value || isNaN(Number(item.amount.value))) {
        errors.push(`Invalid amount value at item index ${idx}`);
      }
      if (!['USD', 'EUR', 'GBP', 'SGD'].includes(item.amount?.currency)) {
        errors.push(`Unsupported currency code [${item.amount?.currency}] at index ${idx}`);
      }
    });

    return {
      valid: errors.length === 0,
      errors: errors.length > 0 ? errors : undefined
    };
  }
}
```

## 4. PayPal API Integration & Webhook Listener (Node.js Controller)

### 4.1 OAuth2 Token Retrieval & Batch Dispatcher

```typescript
// src/backend/paypalService.ts
import axios from 'axios';
import { PayoutGuard } from '../guard/payoutGuard';

const PAYPAL_SANDBOX_URL = 'https://api-m.sandbox.paypal.com';

export class PayPalPayoutService {
  private clientId: string;
  private clientSecret: string;

  constructor() {
    this.clientId = process.env.PAYPAL_CLIENT_ID || '';
    this.clientSecret = process.env.PAYPAL_CLIENT_SECRET || '';
  }

  private async getAccessToken(): Promise<string> {
    const auth = Buffer.from(`${this.clientId}:${this.clientSecret}`).toString('base64');
    const response = await axios.post(
      `${PAYPAL_SANDBOX_URL}/v1/oauth2/token`,
      'grant_type=client_credentials',
      {
        headers: {
          'Authorization': `Basic ${auth}`,
          'Content-Type': 'application/x-www-form-urlencoded'
        }
      }
    );
    return response.data.access_token;
  }

  public async executeBatchPayout(batch: {
    payoutPayload: any; items: any[]; approved: boolean;
    spentTodayUsd: number; allowlist: string[];
  }): Promise<any> {
    const { payoutPayload } = batch;
    // 0. Approval policy FIRST: no human approval, no PayPal call.
    // Over-cap or off-allow-list batches are AWAITING_APPROVAL, never sent.
    const policyErrors = PayoutGuard.validateBatchPolicy(batch);
    if (policyErrors.length > 0) {
      throw new Error(`HumanApprovalRequired: ${policyErrors.join('; ')}`);
    }
    // 1. PayoutGuard Schema Check (own code; APIMatic was build time only)
    const validation = PayoutGuard.validatePayoutPayload(payoutPayload);
    if (!validation.valid) {
      throw new Error(`PayoutGuard Validation Failed: ${validation.errors?.join(', ')}`);
    }

    // 2. Fetch OAuth Token
    const token = await this.getAccessToken();

    // 3. Dispatch to PayPal Payouts REST API with Idempotency Key
    const requestId = `REQ_${Date.now()}_${Math.random().toString(36).substring(7)}`;
    const response = await axios.post(
      `${PAYPAL_SANDBOX_URL}/v1/payments/payouts`,
      payoutPayload,
      {
        headers: {
          'Authorization': `Bearer ${token}`,
          'Content-Type': 'application/json',
          'PayPal-Request-Id': requestId
        }
      }
    );

    return response.data;
  }
}
```

### 4.2 Approve Endpoint (Human Approval Gate)

`POST /api/treasury/batches/:id/approve` — the only path from DRAFT /
AWAITING_APPROVAL to APPROVED. Called by the treasurer clicking
"Approve & Execute" in the grid. The backend re-checks caps, allow-list
and daily spend at approve time (not only at render time), so a
disabled button in the UI is never the only defence. A batch that fails
the policy check stays AWAITING_APPROVAL with the blocking reasons
shown. There is no API path that executes an unapproved batch.

### 4.3 Webhook Handler (`PAYMENT.PAYOUTSBATCH.SUCCESS`)

```typescript
// src/backend/webhookHandler.ts
import { Request, Response } from 'express';
import axios from 'axios';

const PAYPAL_SANDBOX_URL = 'https://api-m.sandbox.paypal.com';

export const handlePayPalWebhook = async (req: Request, res: Response) => {
  const event = req.body;

  // Verify the webhook signature BEFORE trusting the event. No unverified
  // event may update the ledger. Uses PayPal's Verify Webhook Signature
  // API; webhook_id comes from env (PAYPAL_WEBHOOK_ID). The raw request
  // body must be preserved (req.rawBody) for the CRC check PayPal performs.
  const auth = Buffer.from(`${process.env.PAYPAL_CLIENT_ID}:${process.env.PAYPAL_CLIENT_SECRET}`).toString('base64');
  const tokenRes = await axios.post(
    `${PAYPAL_SANDBOX_URL}/v1/oauth2/token`,
    'grant_type=client_credentials',
    { headers: { Authorization: `Basic ${auth}`, 'Content-Type': 'application/x-www-form-urlencoded' } }
  );
  const token = tokenRes.data.access_token;
  const verifyRes = await axios.post(
    `${PAYPAL_SANDBOX_URL}/v1/notifications/verify-webhook-signature`,
    {
      auth_algo: req.headers['paypal-auth-algo'],
      cert_url: req.headers['paypal-cert-url'],
      transmission_id: req.headers['paypal-transmission-id'],
      transmission_sig: req.headers['paypal-transmission-sig'],
      transmission_time: req.headers['paypal-transmission-time'],
      webhook_id: process.env.PAYPAL_WEBHOOK_ID,
      webhook_event: event,
    },
    { headers: { Authorization: `Bearer ${token}`, 'Content-Type': 'application/json' } }
  );
  if (verifyRes.data.verification_status !== 'SUCCESS') {
    console.error('[PayPal Webhook] Signature verification FAILED, ignoring event');
    return res.status(400).send({ status: 'INVALID_SIGNATURE' });
  }

  switch (event.event_type) {
    case 'PAYMENT.PAYOUTSBATCH.SUCCESS':
      console.log(`[PayPal Webhook] Batch ${event.resource.batch_header.payout_batch_id} SUCCESS`);
      // Trigger SSE update to AG Grid Frontend
      global.sseEmitter?.emit('payout_update', {
        batchId: event.resource.batch_header.payout_batch_id,
        status: 'SUCCESS',
        items: event.resource.items
      });
      break;

    case 'PAYMENT.PAYOUTS-ITEM.SUCCEEDED':
      console.log(`[PayPal Webhook] Item ${event.resource.payout_item_id} SUCCEEDED`);
      break;

    case 'PAYMENT.PAYOUTS-ITEM.FAILED':
      console.error(`[PayPal Webhook] Item ${event.resource.payout_item_id} FAILED: ${event.resource.errors?.message}`);
      break;

    default:
      console.log(`[PayPal Webhook] Unhandled event type: ${event.event_type}`);
  }

  return res.status(200).send({ status: 'ACK' });
};
```

## 5. AG Grid Community Integration Spec (Frontend)

**Decision (fixed 2026-11-06): AG Grid Community (MIT), v36.x — NOT Enterprise, NOT Studio.**
The old code imported `ag-grid-community/styles/ag-grid.css` and
`ag-theme-alpine.css`, which no longer matches the current AG Grid API,
and the docs claimed "AG Grid Studio" while shipping a Community grid.
Studio is a separate dashboard-builder product, not a React component,
and any trial licence would expire (Dec 4) before judging ends (Dec 15).
Community is MIT-licensed, needs no licence key, and still qualifies
for the "Best Use of AG Grid" sponsor prize (any AG Grid tool). No
Enterprise feature is used: no Integrated Charts, no Pivoting — the
dashboard shows summary cards computed in-app instead. The grid below
uses the current API: `AgGridProvider` + `AllCommunityModule` +
`themeQuartz` via the Theming API, no CSS imports.


The **Approve & Execute** button is rendered per batch and disabled
unless the batch is within caps (per-item $250, per-batch $500, daily
$1,000 USD-equivalent), every recipient is on the allow-list, and the
GPT-4o recommendation is EXECUTE_NOW. The disabled reason is shown as
the button title. The UI disable is never the only defence: the backend
re-checks the policy in `POST /api/treasury/batches/:id/approve` (§4.2)
and in `executeBatchPayout` (§4.1) before any PayPal call.

## 6. End-to-End Test & Verification Plan

1. **PayoutGuard Validator Test:** Pass an invalid payload (e.g. string amount `"INVALID"`) to `PayoutGuard` $\rightarrow$ verify that API execution is blocked before network request.
2. **PayPal Sandbox Call:** Invoke `executeBatchPayout` $\rightarrow$ verify response code `201 Created` and presence of `payout_batch_id`.
3. **Webhook Simulation:** Trigger mock `PAYMENT.PAYOUTSBATCH.SUCCESS` event $\rightarrow$ verify backend receives event and updates AG Grid state in $< 500\text{ ms}$.
4. **PII Mask Test:** Pass a payload with `receiver: global_vendor_eu@example.com`, `note: 'Pay John Smith'`, `email_subject: 'Payment for Alice'` to `PayoutGuard.sanitizeForLLM` $\rightarrow$ verify the output contains `gl***@example.com` and `[REDACTED]` in every free-text field, and contains NO raw email, NO raw name, NO raw note. The old regex must not be reintroduced.
5. **Approval Gate Test:** Call `executeBatchPayout` with `approved: false`, then with a batch total of $501, then with an off-allow-list recipient $\rightarrow$ verify each call throws `HumanApprovalRequired` and no PayPal request is made. Then approve via `POST /api/treasury/batches/:id/approve` within caps $\rightarrow$ verify the batch executes.
